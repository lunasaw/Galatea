# 09 实施与验收

## 1. 交付顺序

采用纵向切片，每一阶段都有完整用户路径，逐步将原型各区域连接到真实数据。
原型 P01–P15 均为交付范围；阶段切片不等于删除未接入面板或以假状态代替真实执行。

| 里程碑 | 主要工作 | 出口条件 |
| --- | --- | --- |
| M0 契约与基础 | Task/WorkbenchView/Proposal 契约、状态机、持久化、原型六场景 fixture 与逐项对照 | 两阶段/重规划样例校验通过；P01–P15 静态信息完整并标为模拟 |
| M1 可信 App 入口 | 认证、Host 证明与收据、项目/目录/会话激活、完整发起页与导航 | 浏览器握手、自动新会话、跨项目切换及证明测试通过，无错会话写入 |
| M2 数据处理闭环 | Provider/Skill/验证、公开消息与过程卡投影、真实文件 diff、三个详情标签 | 真实两阶段任务完整交付；对话/日志/绑定可追溯，不启动训练 |
| M3 恢复与后台接续 | Host 事件导出、continuation API、Outbox/Inbox、观察与取消 | 浏览器关闭、进程崩溃、重复完成、unknown 均按方案恢复 |
| M4 训练适配 | 治理路线、完整预算卡与三个决定、预授权操作、指标/证据、两类停止 | 方案调整/延后/确认通过模拟联调；另获具体授权后做受治理真实 smoke |
| M5 加固与发布 | 容量、告警、恢复演练、版本锁、部署说明、权限审查 | 确认下述必验矩阵通过，风险与限制可见 |

M2 之前可以做只读快照原型，但不能宣称已有 Agent 自主执行。
M3 之前的演示必须标明依赖用户回到会话继续，不宣称浏览器关闭后已能全程完成。
工期需在 M0 结束后按实现团队、接口改动与验收环境估算，本方案不虚构人日承诺。

## 2. 文件与组件变更范围

### 2.1 新增 galatea-app

按 [目录建议](02-architecture.md) 新建领域层、存储、MCP、Provider、适配器、Worker 和前端。
生成运行时工具 Schema，建立协议版本，提供无秘密的部署配置与数据库迁移。
新增 Skill 应遵循仓库 Skill 目录与原生发现机制，不把固定阶段提示塞到 Host。

### 2.2 通用 Host 增强

| 区域 | 具体改动 | 回归要求 |
| --- | --- | --- |
| AppBridge / Console | 通用工具调用网关，参数绑定的后端挑战与确认收据 | 原有 Hello World、其他 MCP App 仍可正常使用 |
| Host 会话与 App 挂载 | 受认证 app-activations、目录/会话收据、激活状态通道与重新挂载 | 不抢用户焦点、不重复创建、不向旧会话发送；全屏可见可信确认 |
| Host 内部 API | 受认证 continuation 提交/查询/取消，持久化 Inbox | start/steer、原生权限与会话并发不回退 |
| Console 存储与导出 | 公开消息/流式修订、文件变更引用、持久化游标、脱敏与覆盖度 | 不导出内部推理；消息去重、diff 基线正确，不阻塞原生事件 |
| Provider 配置 | 登记外置 Task Provider，无业务模块内嵌 | 管理员明确启用，禁用时 Host 行为不变 |

Host 代码中不出现“训练阶段”“Campaign 预算”等业务分支。
当前 Provider 没有事件生命周期回调，不得为方便把业务订阅硬塞进现有不存在的钩子。

### 2.3 治理服务

首版只使用现有允许的接口，不改治理存储结构、不移除训练边界。
在线创建 Campaign、增加预算或发布动态 Release 属于独立治理项目，
必须有单独的授权协议、并发设计、迁移和验收，不能作为 App 前端功能顺手实现。

## 3. 必验业务矩阵

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| B01 | 用户只要求数据处理 | 恰好两个必要阶段，无训练占位，无 Campaign/训练 Run |
| B02 | 检查后发现编码问题 | 新 revision 插入阶段，已完成 ID 和证据不变，后继依赖正确 |
| B03 | 运行中的阶段被改计划 | 拒绝原地改执行语义，返回明确冲突 |
| B04 | 重复 begin/result/complete | 返回同一收据，不增加 Attempt 或重复事件 |
| B05 | 同 command_id 不同内容 | 幂等冲突，原内容不变 |
| B06 | 工具成功但产物缺失 | 阶段不能 completed，显示验证失败 |
| B07 | turn/completed 但外部仍运行 | Task 保持 waiting_external，不能完成 |
| B08 | 原生计划步骤改变 | 只影响原生详情，不覆盖业务阶段 |
| B09 | 刷新、切聊天再重开 | 从服务恢复一致快照，无假进度和丢失结果 |
| B10 | 浏览器关闭后外部完成 | Worker 观察并通过 Host 接续同一绑定会话 |
| B11 | Host busy | 接续排队，用户输入不被后台 steer 覆盖 |
| B12 | 同一外部完成通知两次 | 只产生一个有效接续和逻辑后续操作 |
| B13 | 超出接续次数或授权过期 | 停止新副作用，给出待办，继续必要外部观察 |
| B14 | 可选阶段跳过 | 保留理由，必需依赖产物仍须满足 |
| B15 | 已完成任务修改目标 | 新建关联任务，不改写已封存结果 |

## 4. 故障与并发矩阵

| 编号 | 注入点 | 预期 |
| --- | --- | --- |
| F01 | Task 事务提交后、Outbox 投递前退出 | 重启后按原 dedupe_key 投递 |
| F02 | 外部提交成功、工具响应丢失 | operation 对账，不能自动再提交 |
| F03 | 原生 turn/start 后网络断开 | Host receipt unknown，按原生日志对账，不盲重发 |
| F04 | Worker 租约过期后旧进程回写 | fencing token 拒绝 |
| F05 | 事件重复、乱序、缺页 | Inbox 去重、重排或补拉，缺口可见 |
| F06 | 取消与外部提交同时发生 | operation 仍被登记并停止/观察，无孤儿工作 |
| F07 | 取消后迟到成功 | 保存观察，不恢复任务，不创建新阶段 |
| F08 | 服务查询返回 404 或超时 | unknown，不当成“未执行” |
| F09 | 数据库从旧备份恢复 | 先只读对账，旧 Outbox 不立即重放 |
| F10 | App 切任务后旧响应返回 | 旧响应被丢弃，选中任务不被污染 |
| F11 | 两个控制请求与计划修订并发 | CAS 生效，重读并重新确认必要操作 |
| F12 | 外部响应在 bind_external 前丢失 | 用 prepare_external 的持久化身份找回原操作，未知时不重发 |

## 5. 身份与权限矩阵

| 编号 | 攻击或误用 | 预期 |
| --- | --- | --- |
| S01 | App 参数伪造 thread_id、principal 或 approved | 不采用，按真实 Host 绑定处理 |
| S02 | 自带 `_meta` 冒充 Host 证明 | Host 丢弃并重签，服务拒绝伪造证明 |
| S03 | 证明换工具、换参数、换服务、过期后重放 | 验证失败或只返回同一已登记收据 |
| S04 | 模型直接调用 App 写工具 | 缺少用户确认证明而拒绝 |
| S05 | 主体 A 读取 B 的 task/artifact/event | 拒绝，且不泄露对象存在性；首版使用两个独立 Host 身份域验证 |
| S06 | Provider 传入不属于当前会话的 task | 绑定校验拒绝 |
| S07 | 路径穿越、符号链接越界、任意 URL | 资源适配器拒绝 |
| S08 | 报告含脚本、隐藏指令或敏感样本 | 安全渲染、内容隔离与脱敏；不提升为系统指令 |
| S09 | App 结果审阅被用于训练或发布 | 不接受，要求对应治理授权 |
| S10 | 未升级 Host 但仍调用任务写接口 | fail closed，不降级信任模型字段 |

证明的防重放必须与业务幂等兼容：相同已受理调用返回原收据，不能创建第二次副作用。
nonce 不是代替 command_id 的另一套可随意变更身份。

## 6. 训练专项矩阵

- 无授权、授权过期、输入 digest 不匹配、预算不足时，不能提交 Job。
- 所有 Training Run，包括 smoke，都经过固定受治理 Ray 入口。
- 新生成代码不是现有 Release 时，停在就绪检查，不自动转向本地训练。
- `raw_logs=false`、`uploads=false` 等能力得到准确 UI 呈现。
- MLflow 通过 API 访问，测试中禁止直接打开 `mlflow.db` 或 MinIO 服务端路径。
- 比较只用兼容 train/validation 证据，最终 test 不参与搜索或重复评估。
- 停止请求、失联、未知、迟到结果保持与治理事实一致。
- `galatea_observe_job` 的恢复副作用单独授权；纯查询不能冒充实时刷新。
- 不自动修改生产 Registry alias。

真实 smoke 必须另有明确的项目、profile、预算和授权。本次文档任务不授权执行训练。

## 7. 测试分层与验证证据

领域单测覆盖状态机、计划无环、CAS、证据门槛与取消规则；存储集成测试使用真实临时 SQLite，
验证事务、重放、租约与迁移；协议测试验证 Schema、错误码与幂等收据。
Worker 和治理测试使用可注入的时钟与模拟 API，不靠长时间 sleep 或实际训练验证恢复逻辑。

浏览器测试使用真实 AppBridge、iframe 与 Chromium，覆盖握手、工具确认、动态阶段、
上下文、主题、右侧固定、全屏、关闭重开、断网和键盘访问。
运行时测试使用固定版本 Codex 与受控模拟模型服务验证真实协议，不把 Mock Provider
返回的成功当作原生端到端成功。

验收报告须记录代码 revision、协议版本、配置 profile、测试命令、结果、跳过项与证据位置。
区分“模拟业务后端通过”“真实 Codex 协议通过”“真实受治理训练通过”，不混为一个通过状态。
已有 Host 文档的历史测试数量不能用作本产品新验收结果。

## 8. 主要风险与处理

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| Host 通用增强大于 UI 工作量 | 只做 UI 无法实现持久自主执行 | M1/M3 设为正式交付，不隐藏为实现细节 |
| 模型未按协议报告 | 操作与阶段脱节 | 状态机限制、未闭合 Attempt 检测、证据核验 |
| 跨进程副作用未知 | 重复训练或孤儿操作 | 持久幂等键、operation 对账、unknown 阻塞 |
| 现有训练授权不能在线扩展 | 用户以为一键批准可用 | 首版预授权；治理扩展单列 |
| 数据敏感或不可信报告 | 信息泄露与注入 | 最小读取、受控预览、untrusted 上下文、权限验证 |
| 原生协议升级 | 接续或事件关联失效 | 固定版本、契约差异检查、分层回归 |

## 9. 可以开始实施的默认决定

本方案已确定：MCP App 形态、唯一 Codex Runtime、外置 Task Provider、可信 Host 网关、
SQLite 单实例、阶段串行、服务端观察和接续、训练双路线显式选择、首版预授权。
界面以原型三栏工作台为基线，包括同源对话、项目自动会话激活、文件 diff、预算卡和三个详情标签。
无需再为这些常规实现选择暂停工作。

上线前仍需填入真实部署配置：身份认证系统、允许的工作区、外部服务 profile、
审批管理员、数据保留策略和具体受治理项目。这些是部署输入，不是让模型猜测的架构参数。

## 10. 原型信息与交互专项验收

本矩阵对应 [第 06 章](06-app-experience.md) P01–P15；先用 fixture 验证视觉与操作完整性，
再以真实来源验证数据连接。两类结果分别记录，fixture 通过不代表真实执行通过。

| 编号 | 对应 | 场景 / 操作 | 必须观察到的结果 |
| --- | --- | --- | --- |
| U01 | P01–P03 | 打开发起页，填写两字段、填示例、提交 | 侧栏与完整表单保留；示例只填表；目录/权限错误就地显示；一次发起创建一个项目/会话 |
| U02 | P01–P02 | 切项目、会话、历史任务 | 名称/slug/目录与绑定一致；真实 Host 激活并重新挂载，切换中不能写错会话 |
| U03 | P04 | 点击阶段条及过程卡 | 只改变详情选择，默认产物；不启动、跳过或完成阶段 |
| U04 | P05–P07 | 数据处理场景 | 目标/来源、Agent 说明、真实 Skill、读取/校验/冻结清单及完成摘要齐全 |
| U05 | P07、P12 | 代码场景，逐个点击文件 | 文件增删改、选中态、真实行级 diff、基线身份、检查中/失败/通过均可看 |
| U06 | P08 | 确认训练场景 | 方案版本、配置、目标、CPU/GPU、内存分项、次数/重试、时长/费用、范围与就绪条件完整 |
| U07 | P08 | 确认、双击、超时重试 | 绑定精确 digest；一次提交意图；旧版本/缺授权不能训练，结果未知先查收据 |
| U08 | P08、P10 | 调整方案 | 只预填并聚焦输入；发送后有真实消息；新方案出现才替代旧卡，旧确认失效 |
| U09 | P08–P09 | 暂不训练、刷新、重新查看 | 不提交 Job；记录与方案保留；重新查看不启动；再次明确确认需重新校验 |
| U10 | P07、P13 | 训练过程场景 | 实际提交/排队/运行、Epoch、Job/Run、指标及观察时间；无数据不伪造值 |
| U11 | P09、P13 | 验收场景与查看证据 | 关联结果卡、可读报告/Checkpoint 验证、终态一致性；smoke 与完整效果明确区分 |
| U12 | P11–P15 | 每个阶段切产物/日志/项目绑定 | 信息随阶段/Attempt 变化，项目会话不漂移；数据统计/清单/切分、文件、训练证据均有内容入口 |
| U13 | P14 | raw_logs=false、某事件未归属 | 日志标签保留真实可用记录，缺失来源明确，未归属事件不猜阶段 |
| U14 | P02、P12 | 选择历史阶段/标签/文件，关闭再开详情 | 选择保留；当前执行与查看状态分开；新消息不抢历史滚动位置 |
| U15 | P10 | 普通追问、Ctrl/Cmd+Enter、IME、网络失败 | 发到绑定会话，真实收据/回复，流式同 ID 更新；失败保留草稿，无假回复 |
| U16 | P10 | 编写时停止 Agent、训练时停止本次训练 | 原型上下文按钮保留；前者不承诺停止 Ray，后者走治理取消，实际停止前反馈正确 |
| U17 | P04–P15 | 只有两个阶段的数据任务 | 布局信息仍完整，无训练占位/预算；三个标签有实际数据产物、日志、绑定 |
| U18 | P04、P06 | 插入修复阶段 | 新 revision 与原因可见，完成阶段/证据/选择稳定，被替代内容明确指向历史 |
| U19 | 全部 | 大屏、900/600 px 附近、窄 iframe、暗色与键盘 | 中心对话为主；窄屏有项目入口，预算/diff/标签不丢失，焦点与状态可访问 |
| U20 | 全部 | 全屏权限确认、重载/断网/会话重挂载 | Host 确认可见；来源/新鲜度正确；无计时器假进度、丢消息或重复执行 |

每个原型场景保存相同输入与视口下的对照截图，并记录所用 task、plan、消息/文件/方案身份。
验收检查信息、操作和真实状态，不能只比页面轮廓或阶段标题。
