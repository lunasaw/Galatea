# 01 产品范围与使用流程

## 1. 目标与输入

产品入口是现有 Codex 聊天。用户新建会话并说明需求，Agent 识别训练、微调、评估或
数据处理任务，在当前会话建立 Task，工具回执同时声明当前任务的 App 展示信息。
Host 根据真实工具事件自动展开右侧任务面板，展示动态阶段、进度、指标、产物和必要确认。
App 不承载项目创建、会话导航、重复聊天记录或输入框。用户一直在原聊天沟通。
详细交互见 [第 06 章](06-app-experience.md)。

用户只需要说明目标、输入位置、结果要求和必要约束。例如：

> 清理这批 CSV，去重并输出质量报告，不需要训练模型。

Agent 应根据输入和可用能力生成阶段，而不是要求用户先选择固定的五步训练模板。
输入位置必须解析到管理员配置的工作区或允许的制品引用；界面展示的路径不等于访问授权。

## 2. 三个代表性流程

### 2.1 只有两个阶段的数据处理

1. 用户提供数据引用和质量要求，启动任务。
2. Agent 生成“检查数据”“清洗并交付”两个阶段及完成条件。
3. 第一个阶段输出字段统计、重复率和异常摘要。
4. 第二个阶段输出清洗后的数据版本和报告；服务校验产物与约束。
5. Agent 提交完成请求，Task Service 检查所有必需阶段和最终交付条件，再将任务置为完成。

App 只显示这两个阶段，不生成空的训练、评估或发布卡片。

### 2.2 执行中插入修复阶段

初始计划为“检查数据 → 清洗并交付”。检查发现编码混杂，继续清洗会丢失字段。

Agent 提交新计划版本：保留已经完成的检查，插入“统一编码”，
把清洗的依赖改为新阶段，并说明原因。App 展示“计划已更新”及差异。
如果修复仍在用户授权的数据处理范围内，服务允许继续；如果需要访问新目录或增加资源额度，
任务进入等待输入或等待批准状态。

动态改计划不能重写已经执行过的历史，也不能把失败阶段从记录中删除。

### 2.3 包含训练的任务

任务可包含数据准备、项目契约检查、Release 就绪检查、训练、结果分析等阶段。
Agent 可以选择合并或拆分展示阶段，但每次训练仍须经过对应治理系统的授权、预算与固定入口。

App 展示完整训练方案与预算卡，保留“确认预算并训练 / 调整方案 / 暂不训练”交互。
执行确认与治理授权分开：当前外部治理 MCP 不具备在线创建授权的能力，
因此“点击批准即可开始任意新训练”是后续治理开发项；首版必须使用已有效授权的执行配置，
或者明确停在等待管理员处理的状态。

## 3. 自主执行的准确含义

Agent 可以自主完成：

- 分析目标、选择已安装 Skill、生成与修订阶段计划。
- 在既定权限与预算内执行工具、检查结果、选择重试或后续步骤。
- 根据结果补充修复阶段、跳过有理由的可选阶段、总结交付物。
- 收到后台服务传回的外部任务事实后，在同一个 Codex 会话继续处理。

Agent 不能自行授予权限、扩大训练预算、批准自己的计划、改写外部执行事实，
也不能只依靠文字声称产物存在。自主程度是任务授权范围内的决策能力。

## 4. 首版产品约束

| 维度 | 首版决定 |
| --- | --- |
| 阶段结构 | 任意数量的有向无环依赖；每个任务同一时刻最多一个执行中的阶段 |
| 会话绑定 | Agent 在当前 Host 会话建立任务，不新建或切换会话；同一会话最多一个活动任务 |
| 多任务 | 不同会话可并行，受 Host 总并发和外部服务限流约束 |
| 工作区 | 绑定受允许的现有项目或新建受限目录；跨目录访问使用现有权限流程 |
| 浏览器关闭 | 已受理外部任务继续被服务端观察；恢复后读取持久化快照 |
| 用户介入 | 可补充目标、调整/延后方案、停止 Agent、恢复或取消作业；停止 Agent 与停止训练明确区分 |
| 暂停 | 停止启动下一阶段；不承诺冻结正在运行的 Ray Job 或原生进程 |
| 训练 | 有效预授权和固定入口；预算或能力不足时明确等待 |
| 交付 | 产物清单、验证结果、任务摘要、可追溯运行记录 |

## 5. 不在首版范围内

- 任意前端 HTML/JavaScript 由模型生成后直接执行。
- 通用拖拽工作流编辑器、并行 DAG 调度器、多 Agent 运行时。
- 独立聊天运行时、重复聊天框、项目启动器、独立权限审批系统、通用终端或代码编辑器。
- 自动对外发布、模型生产别名修改、无授权的昂贵训练。
- 依赖 iframe 常驻或浏览器定时器完成后台任务观察。
- 未经验证就将任意历史任务迁移到另一个会话继续执行。

## 6. 成功标准

两个阶段的数据任务可以完整交付；执行中增加阶段能保留前后计划差异；
刷新、断网、Worker 重启后能恢复状态；重复点击或重复事件不会重复执行；
浏览器关闭后的外部完成可以在授权范围内接续 Codex；取消与未知状态不会导致新训练被误提交。

验收须从新会话的一条需求开始，验证 Agent 工具调用、面板自动展示、实时更新和同会话结果。
这些是目标验收条件，逐项测试定义见 [实施与验收](09-delivery-and-acceptance.md)。
