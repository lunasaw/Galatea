# README 图文导览设计

## 目标

把仓库根目录 `README.md` 从“技术说明中穿插图片”重构为“图解导览 + 技术手册”两层内容。
图片必须承担解释作用：每张图前给出需要理解的核心判断，图后提供简短读图要点和工程含义，
让首次接触平台的读者能够沿着四张图理解平台定位、组件协作、训练治理和项目接入。

## 受众与阅读路径

主要读者是首次接触仓库的算法工程师、模型工程师和平台工程师。

1. 先用四张图在较短时间内理解平台为什么存在、组件如何协作、一次训练如何受治理、
   新项目怎样接入。
2. 再按需查阅部署形态、快速开始、端口、调优、验证、安全和运维文档。

## 内容结构

### 第一层：图解导览

1. **平台定位**：以“一台由 JupyterLab、Ray、MLflow 和 MinIO 共同驱动的训练装置”为
   视觉锚点，说明平台不是单一模型工程。图后用四个短要点解释开发、执行、治理和持久化。
2. **组件协作**：先给出各组件清晰的职责边界，再通过“由小黑踩动、只经过 API 的训练闭环”
   解释数据、任务、记录和 Artifact 如何流转，并强调客户端不得直连后端数据库或对象存储。
3. **训练治理**：用“带着数据版本和 Run ID 转动的训练鼓”串起验证集选参、干净重训、
   最终测试、质量门禁和人工晋级；明确测试集不得回流到调参阶段。
4. **项目接入**：用“可携带的训练项目箱”解释 `configs`、`src`、`scripts`、`tests` 和可选
   `notebooks` 的关系，强调正式训练必须参数化、可追踪、可恢复。

每个图解章节采用相同节奏：核心判断 → 配图 → “读图”要点 → 工程约束。避免为图片重复写
长说明，也不把 README 改成宣传文案。

### 第二层：技术手册

保留并整理现有可操作内容：当前部署形态、快速开始、服务与端口、MLflow 通用调优、示例
工作负载、仓库结构、验证、文档、安全与持久化。命令、路径、端口和安全约束保持准确，
只调整章节顺序和衔接，不扩大平台能力声明。

## 编辑边界

- 不修改训练代码、配置、服务单元或子项目 README。
- 不删除现有部署命令、端口、安全提示和文档入口。
- 不新增未经仓库内容支持的能力、可用性或生产级承诺。
- 不把 Cats vs Dogs 写成平台边界。
- 不处理现有无关的 `outputs/` 目录。

## 验证

- 检查四张图片存在且 README 引用均为有效相对路径。
- 检查所有本地 Markdown 链接存在。
- 运行 `git diff --check`，确认没有空白或补丁格式错误。
- 检查标题层级、代码块闭合和章节顺序。
- 检查 Git 变更范围仅包含设计说明、根 README 和四张配图。
