# P3 独立 validation 数据核验协议 v1

本协议在机器判定前冻结，用于验证话题上下文与真实回复的筛选质量，不是模型训练评估。
配置为 [`topic-validation-v1.yaml`](../configs/topic-validation-v1.yaml)。准备入口将本文件的 SHA-256
绑定到 identity 并复制到受控审核包；后续更改协议必须产生新版本，不能回改本批结果。

## 1. 数据和抽样范围

沿用现有 source/split/consent、v3 前向上下文选择器和固定 tokenizer。只处理 validation 分区；
不修改任何 session 的原切分，不把 train 候选重命名为 validation，不解析 test 消息正文。
原始混合文件只做身份/日期元数据扫描和文件哈希；仅被选中的 validation 行进行正文解码。
未进入冻结 session 血缘的原导入记录直接跳过，不补入 validation。

固定 seed 53，以 `SHA256({day, seed})` 排序抽取最多 50 个 validation 自然日，按
`(session_id, day)` 独立组织；最多解码 12,000 条选中消息。沿用 v3 相邻 self → target 的完整
轮次、最多 64 轮前文和 16 轮模型输入，固定 1,024 序列/256 目标 token 限额，不静默截断。
按 `SHA256({seed, target_ids})` 排序，最多尝试 1,000 个目标，取前 200 个通过确定性检查的候选。

确定性失败或重复窗口单独隔离，记录完整分母；不足 200 时不扩大日期或放宽规则。
机器 keep/reject/uncertain 尚未生成，不参与采样；开始审核后不替换失败、排除或延期项。
分层是固定 200 条上的重叠统计，不是等额分层抽样。结果只适用于本次 50 天内通过结构检查的
候选范围，不能直接外推全部历史聊天；相邻样本可能相关，不按独立同分布宣称总体显著性。

记录与开发 200 条的 source message/session 交集和完整输入输出窗口的精确重复检查。
近重复及将来全量 train/validation 的重复审计仍需单独完成；精确窗口零命中不代表无近重复。
历史 validation 已参加事实记忆处理，保持暴露记录；本批仅与回复选择规则的开发样本分离，
不能称为从未使用的保留集。最终 test 仍需另有未暴露的数据。

## 2. 分层定义

复用已在 train 开发的词表和上下文分层算法；它们是可复算的难度代理，不是语义真值。

| 分层 | 固定定义 | 分母要求 |
| --- | --- | --- |
| ordinary | 不属于短回复、显式引用、交错代理、多类别或 unresolved 类别 | 至少 20 |
| short_reply | 原始目标回复 Unicode 字符数 ≤8 | 至少 20 |
| explicit_reference | 原目标显式引用已通过原子来源、过去时序和所选输入检查 | 至少 20 |
| interleaved_proxy | 保留的前文 topic ID 序列压缩相邻重复后出现再次返回 | 至少 20 |
| low_confidence | 后续任一有效审核器的原始 confidence <0.9；无响应不算低分 | 至少 20 |
| multiple_context_categories | 保留前文出现至少两个已知类别 | 诊断报告 |
| unresolved_category | 选择器类别为 unresolved | 诊断报告 |

层间可重叠，计数不能相加作样本总量；ordinary 不包含全部 200 条。低置信度只在机器响应后
按上述规则赋层，不重采样，也不改变 v4 保留判据。任一关键层不足 20 条就标记证据不足；
不能用总体通过率掩盖缺口，也不能在看过结果后补挑容易样本冒充原验证批次。

## 3. 机器预审与独立参考

机器预审继续采用冻结的 v4 prompt、JSON Schema 和判据：双模型均 keep、有共同原子 self
回应锚点且没有适用的硬风险才建议保留。单模型有效排除或延期不为提高保留率重问。
GPT/Claude 的原始判断、未校准分数、必要上下文索引和不确定性证据独立记录。
两者一致只能说明机器共识，不能作为自身的精度参考答案。

本轮仅准备样本和盲审包，不发送请求。后续独立执行适配必须支持 validation 的真实 split，
不能临时把样本改成 train 来绕过旧解析器。请求格式已验证与同内容的 v4 请求一致；响应校验、
身份熔断、预算预留、仅失败项恢复和不可变封存需在新入口完成后才能执行。

预留下一阶段单条请求、两并发，400 次首轮（200×2），最多另 40 次失败修复；每项最多修复一次，
按冻结 ID 顺序使用修复预算，不用完后递归加预算。输入上限 1,800,000、输出预留上限 1,760,000、
单次输出 4,000 token、超时 240 秒。样本准备报告只计算 payload 输入估算，不把预留当作实际用量
或价格；该入口的实际外部请求数固定为 0。正式调用前需核验当时的精确模型路由身份。

独立参考覆盖全部 200 条，含机器建议保留、排除和延期；参考审核者不看到机器判定、分数或旧分组。
先只看模型实际输入和原回复，标注回应关联、输入所指完整性、沟通行为、风险、原子回应对象和
必需上下文；再查看同日、同 session、目标之前最多 64 轮的可用前文，判断是否漏掉了证据。
只在扩展前文出现的必要证据不能让原模型输入被判为完整。缺失媒体、未提供线下安排或前文
未覆盖的所指保持未知；引用范围、参考身份及候选 digest 必须明确记录。

本次输出静态盲审页面，不在浏览时记录已审核，不生成空白“人审完成”事件。
若后续用机器做参考，其结果只能称为机器审计支持率；同模型或同网关的相关错误需要注明，
不能冒充独立人工真值或训练资格。

## 4. 固定统计口径

每项报告分子、分母、未知量和描述性的 Wilson 95% 区间；同 session 的相关性限制使该区间
不能直接解释为总体覆盖率保证。分母为零或参考缺失时报告不可估计，不填 0 或 100%。
以下门槛沿用实施计划建议并在判定前固定；未知参考计入未核实分母，不默认为正确。

| 指标 | 分子 / 分母 | 目标 |
| --- | --- | --- |
| 回应关联正确率 | 独立参考核实有关联且原子锚点正确的候选 / 全部 200 条 | ≥98% |
| 模型输入完整率 | 独立参考核实仅凭模型输入即可理解具体所指的候选 / 全部 200 条 | ≥95% |
| 机器保留 precision | 独立参考核实所有保留条件成立的机器保留样本 / 所有机器保留样本 | ≥95% |
| 误排比例 | 独立参考认为可保留的机器排除样本 / 所有机器排除样本 | 报告，不预设达标线 |
| 延期可用比例 | 独立参考认为可保留的延期样本 / 所有延期样本 | 报告，不并入误排 |

总体和每个关键层分别报告上述指标，保留交叉表、未完成机器响应和未完成参考数量。
身份、授权、因果、角色、隐私/canary 硬检查必须全部通过；原文与 token 边界不能变化。
未全量回收 400 个有效机器判断、未完成独立参考、关键层不足或近重复审计未完成，均不能宣布
P3 验收通过。即使机器审计的数值通过，也不自动授予正式数据资格或启动 P4。

## 5. 不可变产物与范围

使用独立 `topic-reply-validation-candidate-v1` Schema；由冻结 train Schema 作显式版本适配，
只改变版本与 split 常量，原 train Schema、v3/v4 源码及历史产物不改写。验证后的 Schema 随包封存。
`validation.candidates.jsonl` 是审核输入，不能当作正式 validation snapshot 或训练集使用。

受控包绑定 source/split/consent、开发和完整审核 manifest、选择器/tokenizer、协议/Schema、源码
与配置 digest；目录 700、文件 600，原子发布、不可变重放、改动拒绝。保留 count-only 报告、
分层成员、隔离记录、无模型判定的审核页和可用前文；私人正文不进入公开文档或终端输出。

保持 `training_run=false`、`human_review_completed=false`、`formal_training_eligible=false`、
`promotable=false`。不加载模型、不产生参数更新、MLflow Run、checkpoint 或模型别名变化。
