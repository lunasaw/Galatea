# 06 App 界面与交互

## 1. 页面结构

```text
Host：聊天、原生工具过程、权限确认、会话切换
┌────────────────── Galatea MCP App ──────────────────┐
│ 任务名称 / 状态 / 最新计划版本 / 状态更新时间         │
│ 目标与输入摘要                暂停 / 恢复 / 取消       │
├──────────────────────┬─────────────────────────────┤
│ 动态阶段列表         │ 当前阶段详情                 │
│ 1 检查数据 ✓        │ 输入 / 完成条件 / 实际操作    │
│ 2 统一编码 →        │ 验证结果 / 产物 / 等待原因    │
│ 3 清洗并交付 …      │ 相关 Run / Job / 事件记录     │
├──────────────────────┴─────────────────────────────┤
│ 计划变更提示 / 用户待办 / 最终交付                   │
└─────────────────────────────────────────────────────┘
```

内联模式优先展示摘要和阶段，右侧固定适合伴随聊天，全屏适合数据与报告查看。
窄屏按“任务摘要 → 阶段列表 → 选中详情”排列，不要求三栏同时可见。
历史任务列表可以放在 App 内抽屉，不能尝试修改 Host 会话侧栏 DOM。

## 2. 动态渲染契约

App 按快照的 `stages[]` 渲染，不按标题判断业务类型，不假设固定阶段数量。
`stage.kind` 选择展示组件，`status` 选择状态，`acceptance` 和 `evidence_refs` 提供实际内容。

| kind 示例 | 首版组件 | 主要内容 |
| --- | --- | --- |
| `data.inspect` | 数据摘要 | Schema、统计、质量问题、报告 |
| `data.transform` | 处理结果 | 输入输出版本、样本数量、规则与验证 |
| `code.prepare` | 代码摘要 | 改动文件引用、检查结果、进入 Host 查看差异 |
| `training.run` | 运行面板 | 授权、operation/job/run、资源、验证指标 |
| `result.review` | 结果面板 | 报告、产物、验收、人工审阅 |
| 未知 kind | 通用阶段面板 | 标题、状态、输入输出、证据、错误 |

组件注册表随前端发布，模型只选择声明的类型和结构化数据。
模型文本按安全 Markdown 渲染，禁用原始 HTML、脚本、危险 URL 和任意 iframe。
动态阶段不要求动态加载模型生成的 React/JavaScript。

## 3. 初始化与数据读取

1. `new App(...)` 后注册 SDK 回调，再执行 `App.connect()`。
2. 接收入口工具的参数与结果；将其中的 task_id 视为选择意图，由服务检查权限。
3. 调用 `get_task` 获取权威快照，以 `last_event_seq` 作为基准。
4. 调用 `get_task_events(after_seq)` 拉取增量，应用可识别事件；结构变化或无法应用时重读快照。
5. 从快照读取 `allowed_actions` 决定按钮；服务执行时再次校验，前端禁用不是安全边界。

事件必须按 seq 顺序处理，重复忽略，缺口重拉；分页耗尽后才推进已完整应用的游标。
游标过期返回 `CURSOR_EXPIRED`，客户端重取快照而不是从零拉取全部日志。
请求返回时检查 task_id 和当前加载 generation，避免切换任务后旧响应污染新页面。

首版不依赖 Host 尚未支持的资源订阅：

- 活动页面运行任务每 2 秒增量轮询，加入随机抖动；无变化后退避到 5 秒。
- waiting_external 每 5–10 秒查询业务摘要；真正外部观察由 Worker 执行。
- document.hidden 时退避到 30 秒，恢复可见立即获取快照。
- 终态停止高频轮询；断网使用 2/5/10/30 秒退避并保留最后观察时间。
- 每视图只允许一个查询在途，销毁时取消计时器和未完成读取。

这些是待调优默认值，轮询本身不能触发 Agent、外部提交或状态变更。

## 4. 表单、状态与上下文

权威 Task 和已提交输入保存在服务端。选中阶段、标签页等可重建状态只保存在 iframe 内存；
需要跨刷新保存的目标草稿通过受控服务写入，并显示保存状态。
不能依赖 opaque-origin iframe 的 localStorage、Cookie 或与 Host 同源访问。

App 可以通过 `ui/update-model-context` 提交精简上下文：

```json
{
  "task_id": "task_demo",
  "selected_stage_id": "stage_clean",
  "plan_revision": 2,
  "observed_task_version": 12,
  "selected_artifact_ids": ["artifact_report"],
  "selection_summary": "用户正在查看清洗阶段的质量报告"
}
```

上下文不放完整日志、数据样本、秘密或执行令牌。它是 untrusted 的阅读线索，
Agent 执行前必须通过 Task 工具读取最新状态。
Host 当前每聊天最多 32 个实例、上下文总量 256 KiB，App 建议单实例控制在 16 KiB 内。

## 5. 用户操作语义

| 操作 | 通道 | 明确语义 |
| --- | --- | --- |
| 查看阶段、筛选、预览 | App 本地 / 只读工具 | 不启动 Agent |
| “解释这个结果” | ui/message | Host 确认后由 Agent 解答 |
| 开始任务 | create_task(start=true) | 一次确认、一次持久化启动请求 |
| 修改约束、回答等待信息 | submit_input | 校验目标请求与版本，必要时生成重规划接续 |
| 暂停 / 恢复 / 取消 | request_control | 先持久化控制状态，再按执行能力处理 |
| 审阅当前结果 | record_review | 仅绑定该结果 digest，不是训练或发布许可 |
| 训练预算处理 | 治理状态面板 | 首版展示已有授权或管理员待办 |
| 下载产物 | SDK 下载请求 | Host 确认、资源与大小限制、服务再次鉴权 |

Host 负责可信确认，App 不再叠加第二个相同的“确认框”。操作按钮 pending 时禁用重复提交，
重试使用原 command_id；pending 超时先查询收据，不把按钮恢复成可任意重新执行。

## 6. 空态、错误和冲突

- 无任务：展示目标输入与能力说明，不默认生成训练任务。
- 正在规划：显示 Agent 正在准备计划，不预先插入五个占位阶段。
- 新计划：显示新增/替代及原因；保持用户选中稳定 stage_id，失效时明确跳转。
- 权限不足：展示缺少的具体范围和申请入口；不把授权失败误报为数据质量问题。
- 外部状态未知：展示最后确认事实、时间与正在对账；禁止“再运行一次”快捷按钮。
- 版本冲突：重取最新状态，保留尚未提交的文本；用户控制请求必须重新确认改变后的目标。
- 能力不支持：例如 raw logs 或在线批准未提供，显示明确状态而非空白加载。
- 服务不可达：保留只读快照并标为过期；不能修改本地状态模拟成功。

## 7. 产物展示与访问

使用受控类型预览 JSON、文本、图像、表格摘要和指标；大型原始数据按页或统计查看。
所有 Artifact 由 opaque ID 解析，校验 Task 归属、类型、大小和允许的读取范围。
本地路径经过真实路径解析，拒绝路径穿越和符号链接越界；远程 URL 只能由服务适配器解析。

当前 Host 下载上限为 8 个文件、单文件 8 MiB、合计 16 MiB。
超过限制时展示“在受控制品服务下载”的链接，由服务提供短时、最小范围访问能力，
经 Host 外链确认打开；此能力需独立实现，首版未配置时明确标为不可下载。
不要把大型文件 base64 填进模型上下文或工具结果。

## 8. 可访问性与性能

阶段和操作均支持键盘访问，状态使用文字与图标，不只依赖颜色。
状态变化使用适度 aria-live 提示，轮询无变化时不重复播报。
长列表分页或虚拟化，日志懒加载，图表按需渲染。

UI 只负责展示，任何组件异常都不能改变任务执行状态；重载 iframe 后必须能重建当前任务。
