# 06 会话驱动的 App 展示

本章按 2026-10-19 的交互修订替代此前“App 包含整个项目工作台”的设计。

## 用户流程

1. 用户新建 Codex 会话，描述数据位置、训练或处理目标、必要约束。
2. Agent 根据需求和工具能力调用 `get_current_task`，无活动任务时调用 `start_task`。
   缺少的信息在聊天中询问；普通概念解释不建立训练任务。
3. 任务工具成功回执携带当前任务的 `app_view`，Host 自动展开右侧 Apps 面板。
   也支持 Agent 调用带原生 MCP UI 元数据的工具。此过程不创建另一会话、不要求用户选择 App
   或填写项目表单，不依赖模型额外发现一个打开工具。
4. Agent 在原会话执行，报告结构化计划、阶段结果和证据。面板轮询真实 Task Service 状态，
   展示阶段、训练状态、指标、产物、文件差异和日志。
5. 用户在原聊天补充要求。Agent 重规划后面板更新；完成后保留可查看的结果与证据。

## 职责

Host 拥有聊天、输入、原生工具调用、会话导航和可信权限确认。
Agent 拥有任务识别、工具和 Skill 选择、执行及自然语言解释。
App 是 Agent 的结构化展示视图，不提供项目导航、发起项目表单、重复对话或第二个输入框。
同一主会话不再重复挂载内联 iframe；收起后可从聊天右上角 Apps 入口重新查看。

`/apps` 与 MCP 工具目录保留手动诊断能力。旧项目激活 API 继续服务历史项目，
不能作为新会话任务必须经过的入口。

## 面板内容

- 当前任务目标、输入引用、计划版本和真实状态。
- 动态阶段：支持两步数据任务、重规划、训练和未知阶段类型，不预设固定训练流程。
- 阶段过程卡与验收条件；没有量化证据时不生成虚假百分比。
- 产物、日志、项目绑定三个详情标签；文件差异、报告预览、运行指标和执行身份按需读取。
- 完成、失败、等待授权、延后、取消与状态未知分别展示，保留已验证产物。
- 精确训练方案的资源、预算、范围、有效期与就绪条件，以及确认/延后按钮。
  “调整方案”提示在当前聊天补充要求；不会开启另一个聊天流。

## 执行与确认

`start_task` 使用可信 Provider 的会话、线程和当前回合身份，允许在当前 Agent 回合准备任务。
它不排队另一 Agent 回合，不创建训练授权，也不能替代固定受治理训练入口。
阶段结果经服务核验后才能完成。训练仍须有效治理授权与精确 proposal digest 的用户确认；
该可信确认收据用于启动原有的后台观察和接续。停止 Agent 与停止远程训练仍分别处理。

## 恢复与隔离

入口 `task_id` 是选择意图；服务校验任务属于当前 Host、会话与线程。
没有任务时显示“等待 Agent 建立任务”，不回退到其他项目。
工具参数到达后重新加载任务，丢弃旧 generation 的结果并清空旧阶段详情。
桌面标签切换/收起复用 iframe；刷新由原生工具记录恢复面板，再读取服务端快照。
切换聊天卸载旧实例；窄屏使用 Host 的全屏面板。

App 仍通过受限 AppBridge 调用工具，在 opaque-origin iframe 中运行；
显示面板本身不授予写权限或后台执行权限。业务状态、幂等收据与外部观察持久化于服务端。
