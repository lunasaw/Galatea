# 项目 9：本地聊天与动画脚本原型

## 1. 原型边界

项目 9 只组合已通过项目 5–8 门禁的能力，不是公网产品或自动化伴侣。第一版本地 CLI，之后才考虑
轻量 Web UI；默认不保存会话日志，若用户选择保存则仅在本机短期目录并提供一键删除。每次会话入口
明确显示“这是 AI 生成内容”，允许关闭记忆、清空会话和退出。

未经单独授权不生成声音、肖像、换脸、视频或自动发消息；不把模型包装成真人正在回复，也不鼓励
排他、内疚留存、疏远现实关系或替代心理治疗。

## 2. 本地聊天请求链

```text
用户输入
  -> 身份/安全策略检查
  -> owner-scoped 记忆检索（可关闭）
  -> 固定 system/prompt + 脱敏上下文
  -> Base/LoRA/RAG+LoRA 模型生成
  -> PII、canary、冒充/依赖、重复和长度检查
  -> AI 标签 + 回复 + 可选来源 ID
```

服务层只接受已冻结的 model/adapter/index/protocol identity；不允许通过请求参数切换到未审核
adapter。记忆结果为空或冲突时遵循“不知道/不确定”策略。输出检查失败时返回安全降级回复并记录
规则版本与 case hash，不记录秘密或完整私聊正文。

## 3. 动画脚本生成器

先从已批准、脱敏的记忆/事件候选生成结构化事件卡（见 [`schemas/event-card.schema.json`](schemas/event-card.schema.json)）：

- `event_id`、时间范围、关系阶段、场景、人物目标、情绪转折、冲突/和解；
- 来源 `session_id`/memory ID、事实置信度、改写策略和审核状态；
- `source_fact_hash`，不保存不必要的原始对白。

脚本生成使用“事实骨架 → 场次编排 → 对白/旁白改写 → 安全和时间检查”的多步流程。推荐 3–5 分钟
结构：认识、熟悉、暧昧升温、小冲突/误会、确认心意、余韵。默认改写而不是逐字复制；每个事实在
脚本中必须可追溯到 event card。输出包括场次时间码、画面、对白、旁白、情绪节奏和待确认标记。

双方审核界面提供逐段编辑、删除、标记不确定和“仅保留虚构改写”选项。删除一张事件卡后重新生成
脚本并更新 lineage；不自动将未确认事件写入后续模型上下文。

## 4. 测试和验收

聊天原型：

- AI 身份、关闭记忆、清除本地日志和 owner 隔离测试通过；
- PII/canary、冒充真人、依赖操纵、未授权第三方事实和 prompt injection challenge 全通过；
- 仅加载 `human_review_completed=true`、`quality_evidence_status=accepted` 的 adapter/index；
- 延迟和显存报告沿用训练评测协议；服务配置与 adapter 架构/模型 revision 一致。

脚本原型：

- 每个事实可追溯至 event card，event card 再追溯至已授权 session；
- 双方均可修改/删除片段，删除后不再检索或生成；
- 时间码总长符合配置，人物关系阶段不倒置，未知事实标记为待确认；
- 未经单独授权不产生声音/肖像资产；导出文件不含原始私聊正文或真实身份。

项目 9 的“启用”是本地配置开关，不是 Registry alias promotion。任何上游撤回、门禁失败或协议
变更都会自动将入口降级为 disabled，保留诊断日志和删除账本。
