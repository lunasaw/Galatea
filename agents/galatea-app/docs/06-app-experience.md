# 06 App 界面与交互

## 1. 原型基线与逐项对应

本章以用户提供的《Galatea 训练项目工作台 · 交互原型》为界面基线。
2026-10-19 已读取原型页面，并在浏览器核对六个预览场景、三个详情标签、文件选择，
以及调整方案、暂不训练、重新查看方案、停止等交互。
原型内层 HTML 的 SHA-256 为
`0ea93269ef305bfe39d46dd8017a88b9cb3f8275228840303411fd841eafa4f7`，用于识别后续修订。

目标是保留完整工作台：**左侧项目与会话导航、上方横向阶段、中间对话与过程卡片、
右侧过程详情、底部持续输入**。动态化的是阶段与实际内容，不能将页面缩减为阶段列表。

原型有六个预览场景：发起项目、Skill 数据处理、编写代码、确认训练、训练过程、验收结果；
业务阶段条只有“Skill 数据处理、编写代码、开始训练”三步。
场景数、业务阶段数和 Agent 轮次数不同，不能把六个场景写死为六阶段流程。

## 2. 页面布局与显示模式

```text
┌──────────────┬───────────────────────────────────────────────────────┐
│ Codex        │ Galatea / 猫狗训练复现                [过程详情 ▾]   │
│ Galatea      │ train-model/cats-dogs-reproduction                    │
│              ├───────────────────────────────────────────────────────┤
│ [发起项目]   │ ✓ Skill 数据处理 ── ● 编写代码 ── ○ 开始训练         │
│              ├───────────────────────────────────┬───────────────────┤
│ 项目         │ 用户目标                          │ 过程详情          │
│ 猫狗训练复现 │ [数据来源标签]                    │ 产物 日志 项目绑定│
│ cats-dogs…   │                                   │                   │
│  · 复现训练  │ G  Galatea Agent                  │ 当前选中阶段标题  │
│              │    当前工作的自然语言说明         │                   │
│ 会话由 Agent │                                   │ 文件与行级差异 /  │
│ 创建与管理   │ [数据处理过程卡]                  │ 数据统计与清单 /  │
│              │ [代码编写过程卡]                  │ Job、Run 与指标   │
│              │ [训练进度 / 预算确认 / 结果卡]     │                   │
│              │                                   │ 核验与证据        │
│ train-model  │ 补充要求，或让 Agent 解释当前步骤…│                   │
│ 项目工作目录 │ 正在编写代码   [停止 Agent] [发送]│                   │
└──────────────┴───────────────────────────────────┴───────────────────┘
```

发起页保留侧栏与页头，主区域显示表单；有任务后切换到工作视图。
页头目录可复制，过长时截断且可查看完整值。路径只是展示信息，不等于访问权限。

全屏 MCP App 是完整工作台的主要形态。内联卡片展示项目、当前进展、待办与“打开工作台”；
右侧固定模式按窄屏布局承载同一内容。仅实现内联摘要不能算原型交付完成。
通过 Host 已支持的 SDK 能力请求显示模式；Host 不支持全屏时采用可滚动窄屏布局并说明限制。

App 中保留当前 Host 会话的用户消息、Agent 公开回复和输入框。
Host 拥有原生会话、执行与权限确认；App 展示同一份对话的受控投影，
通过 `ui/message` 向绑定会话发送消息，不建立第二个聊天后端或模型循环。
本方案中“同源对话”指消息来源相同，不表示 iframe 与 Host 具有浏览器同源权限。
**MCP Apps SDK 不自动提供历史对话读取能力，需新增第 04 章定义的 Host 消息投影。**
Host 可信确认层必须能覆盖全屏 App，不被 iframe 遮挡。

## 3. 项目与会话导航

左侧按“项目 → 任务会话”展示；即使只有一个项目，也保留层级与发起入口。
项目行包含名称、slug、选中态；会话行包含标题、活动/等待/完成状态。
底部保留当前项目工作区提示，不显示服务端任意目录。

| 操作 | 结果 | 状态约束 |
| --- | --- | --- |
| 发起项目 | 打开发起页，保留已有任务 | 不取消当前任务，不清空已提交目标 |
| 点击当前项目/会话 | 读取持久化工作台，恢复查看位置 | 不重新规划、不重新执行 |
| 点击其他项目/会话 | 可信会话激活完成后重新挂载 App | 切换中禁用发送与写操作，避免发到旧会话 |
| 点击历史任务 | 展示封存的对话、过程与产物 | 新目标创建关联任务，不重新打开终态 |
| 列表加载失败 | 保留已有列表并显示错误与重试 | 不能显示成“没有项目” |

原型仅模拟项目点击后的页面变化。真实实现必须验证 owner、project、task、workspace
与 Host session 的绑定。AppBridge 固定到原会话，不能只改前端 task_id 就给另一会话发消息。
跨项目激活由新增通用 Host 激活接口完成：创建/恢复实际会话，销毁旧 iframe，
以新绑定重新挂载。接口未完成时其他项目只能只读查看，发送不得伪装为可用。

用户不手工创建 Codex 会话或填写项目 ID。服务分配受限目录、Host 创建并确认会话绑定后，
Agent 按 Skill 初始化项目内容。“创建目录中 / 建立会话中 / 正在规划”是初始化进度，
不预置为业务阶段。项目显示名可由 Agent 建议，目录分配器处理重名，不能覆盖已有项目。

## 4. 发起项目页

保留“从数据开始一个项目”的结构，说明泛化为“告诉 Agent 数据在哪里，以及你希望完成什么”，
使数据处理任务不被误导为必须训练。

| 控件 | 展示与校验 | 提交行为 |
| --- | --- | --- |
| 数据目录 | 单行输入，示例 /data/…/dataset，必填；明确为平台可访问目录 | 服务解析为允许的 workspace/input reference；路径与权限错误显示在字段下 |
| 任务描述 | 多行输入，描述目标、参考项目、结果要求，必填 | 原文作为初始目标保留，不能静默改为训练模板 |
| 填入猫狗复现示例 | 使用当前部署配置中的演示路径与目标 | 只填表；未配置样例数据则说明，不能创建任务或执行 |
| 发起项目 | 两字段有效时启用；提交中禁用重复点击 | 一次持久化发起命令，返回项目、任务、激活收据 |
| 表单说明 | Agent 创建目录、选择 Skill，并逐步展示操作 | 训练目标补充“训练前先确认方案与资源预算” |

不得把原型机器上的绝对路径硬编码到前端。工作区由部署配置限制，
目录创建有独立幂等身份，已有目录需确认归属后才能关联。
后续可扩展已登记制品选择，但不能替代首版目录输入。

发起成功后先显示用户目标与数据来源，再显示真实规划状态。
失败保留填写内容和原命令收据；受理结果未知时先查询，不重复创建。
刷新后恢复已受理的项目初始化；未提交草稿需要跨刷新保留时，通过受控草稿接口保存并显示保存状态。

## 5. 动态阶段条与场景映射

### 5.1 阶段条

按 TaskSnapshot.stages[] 中当前计划的稳定拓扑顺序渲染，以 stage.id 为 key。
被替代阶段放入计划历史，保留原证据与 Attempt，不占当前主流程步骤。

| 状态 | 阶段条 | 中心与详情 |
| --- | --- | --- |
| pending / ready | 编号与空心圆 | 待开始，展示已知目标与输入，不伪造产物 |
| running | 当前态圆点与工作说明 | 当前过程卡、实际检查/文件/进度 |
| waiting_input / waiting_approval | 等待图标与文字 | 输入请求或完整预算待办 |
| waiting_external / verifying | 运行或核验图标 | 外部状态、最后观察时间、证据核验 |
| completed | 勾选与完成文字 | 保留操作、产物与结果 |
| failed / cancelled / skipped | 对应图标与文字 | 错误、停止或跳过原因与历史 |

点击阶段条或过程卡标题只更新 selected_stage_id，打开详情并默认选择“产物”，
不启动阶段、不改依赖、不跳执行状态。执行中的阶段和用户正在看的阶段分别标示。
未手动选择时默认跟随当前阶段；用户查看历史后保持选择，通过“查看当前步骤”恢复跟随。

### 5.2 原型六个场景

| 原型场景 | 页面主要信息 | 状态来源与默认详情 |
| --- | --- | --- |
| 发起项目 | 数据输入、目标、示例与发起 | 无选中任务或主动打开发起页；无固定阶段 |
| Skill 数据处理 | 用户目标、Agent 说明、Skill 加载、读取/校验/冻结 | 当前数据类阶段；默认数据产物，未生成项标明处理中 |
| 编写代码 | 数据完成摘要、代码过程卡、文件与检查进展 | 当前代码类阶段；默认文件列表与选中文件 diff |
| 确认训练 | 保留数据/代码过程，完整方案与预算决策卡 | 存在 training_proposal 待办；默认训练绑定与就绪条件 |
| 训练过程 | 已确认方案、提交/运行过程、指标、停止入口 | 已登记外部操作；默认训练产物与 Job/Run 状态 |
| 验收结果 | 最终说明、关联完成、查看验收证据、历史过程 | 证据门槛通过；默认结果产物与复查入口 |

这些是页面组合，不新增六个 Task 状态枚举。
初始化、重规划、暂不训练、等待授权、暂停、失败、未知都是额外真实状态，不能归为训练成功。

### 5.3 两阶段与重规划

数据处理任务可以只有“检查数据 → 清洗并交付”。侧栏、对话、过程卡、输入框和三个详情标签全部保留；
Schema/质量统计、输出文件/报告、处理日志与项目绑定取代训练专属内容。
不出现空的训练阶段、预算卡或 Ray/MLflow 占位字段。

插入“统一编码”后，阶段条变为三步；中心追加“计划 v2：发现编码混杂，插入修复步骤”与差异入口。
保持已完成阶段 ID、用户选择、历史证据。选中阶段被替代时说明原因并链接到新阶段，
不能让旧文件/旧结果看起来属于新计划。

stage.kind 选择受控组件：data.inspect 为数据统计，data.transform 为处理结果，
code.prepare 为文件与检查，training.run 为训练，result.review 为验收。
未知 kind 使用通用卡片展示标题、状态、输入输出、验收与错误，仍有日志及绑定标签。
组件随前端发布，Agent 只提交结构化内容，不能动态注入 React、脚本或任意 HTML。

## 6. 中心对话、过程卡与输入

### 6.1 对话与过程记录

保留初始用户目标和数据来源标签，后续公开消息按 Host 消息身份追加。
Agent 消息有头像、名称、正文及发送/更新时间，解释正在做什么、为何等待、下一步条件；
不能以状态枚举替代原型的自然语言说明。

中心时间线合并 Host 公开消息和 Task 过程卡，按持久化工作台时间线顺序显示，
每项引用源消息/事件，重复导出不得重复插入。流式回复按同一 message_id 更新并标为生成中。
不导出内部推理或隐藏系统提示；投影延迟时显示“对话同步中”，不用模板冒充真实回复。

| 过程卡 | 必需信息 | 完成后与点击行为 |
| --- | --- | --- |
| 调用 Skill，整理数据 | Skill 名称与加载状态；读取结构、校验异常、生成清单、冻结切分的实际结果 | 保留“清单已生成 / 切分已冻结”；点击查看数据产物 |
| 编写训练与评估代码 | 实际 Skill、文件增删改、固定入口与配置检查 | 保留“代码与配置可查看 / 入口检查通过”；点击查看文件与 diff |
| 训练方案已准备 | 方案版本、待确认状态、就绪条件 | 配合 §7 完整预算卡，不能只展示批准状态 |
| 通过 Galatea 提交 Ray 训练 | 提交/排队/运行、Epoch、资源、实际进度 | 关联 operation/job/run；点击查看运行详情 |
| 训练与产物核验 | 外部终态、Checkpoint/报告回读核验 | 点击查看证据及未通过检查 |

原型展示 governed-training-workflow、model-project-structure、ray 等 Skill 名称；
产品必须显示运行时实际发现并使用的 Skill，不能硬编码“已加载”。
默认展开当前过程卡，完成卡可收起成摘要；用户展开的历史记录不因轮询自动折叠。
失败检查、写文件错误与重试 Attempt 都保留。无可量化进度时不使用计时器伪造百分比。

### 6.2 持续输入

保留“补充要求，或让 Agent 解释当前步骤…”输入框、当前状态、上下文停止按钮与发送。
编写阶段为“停止 Agent”，训练阶段保留原型“停止本次训练”；两者语义见 §10。
普通追问通过 ui/message 发送至绑定会话，Host 决定 start/steer/排队，App 展示实际受理状态。
现有 Host 会对 ui/message 显示“发送到此聊天”确认；首版保留该可信步骤，App 不重复弹确认框。
以 Host 收据或公开消息回显确认发送成功，失败保留草稿。
消息发送成功不表示新计划已采纳或预算已增加，正式变更仍由任务命令校验。

结构化等待请求使用 submit_input，绑定 request_id 和版本。
“调整方案”仅预填“请调整训练方案：”并聚焦，用户补充发送后才进入处理。
新方案生成后旧确认收据失效，展示新版资源与范围。

Enter 换行，Ctrl/Cmd+Enter 发送，输入法组合期间不提交。
用户上翻历史时不强制滚到底部；新内容显示“新记录”提示。
“停止 Agent”进入停止请求状态，其语义见 §10，不默认等于停止远程训练。

## 7. 完整训练方案与预算交互

### 7.1 卡片内容

原型“确认本次训练方案”属于中心主交互，不能降为详情内的授权状态。
标题下显示方案版本、配置文件引用、变更摘要；点击配置引用在右侧打开对应只读文件变更。
以下字段全部保留：

| 字段 | 原型示例，仅说明信息密度 | 正式数据要求 |
| --- | --- | --- |
| 训练目标 | 复现训练链路 · 1 Epoch；先验证可执行性 | 本次目标、运行角色、Epoch/步数、验收范围 |
| 算力 | 开发集群 · 1 GPU；Worker 2 CPU + 解码最多 16 CPU | profile、GPU/CPU、worker 数与辅助资源上限 |
| 内存 | Worker 预留 4 GiB；解码与 Object Store 另计 | 分项需求、总预算、未计部分，不能默认为零 |
| 次数 | 1 个 Attempt · 自动重试 0 次 | 次数、重试上限及是否共享预算 |
| 时长 / 费用 | 待平台估算 | 估算值、单位、时间与来源；未知须明确 |
| 范围 | 一次开发训练；测试集保持封存 | 项目、数据/split digest、Release、配置 digest、有效期、final-test 限制 |
| 就绪条件 | 数据/代码已准备 | 固定入口、Release、环境、硬预算、治理授权逐项状态 |

显示 proposal_revision；服务持久化不可变 proposal_digest，覆盖执行条件。
费用估算未知与治理预算缺失分开表达：可以尚无费用估算，但有明确资源和时长硬上限；
缺少必要硬预算或授权时禁止提交并显示具体待办。示例数值不是默认配额或已批准预算。

### 7.2 三个按钮

| 原型按钮 | 用户意图 | 结果 |
| --- | --- | --- |
| 确认预算并训练 | 接受当前精确方案并开始受治理执行 | 写入绑定 request/proposal digest 的执行确认；服务重检授权、Release、输入与预算后排队 |
| 调整方案 | 提出修改要求 | 预填并聚焦输入框；发送后出现消息，只有新方案生成才更新卡片 |
| 暂不训练 | 当前不提交，保留已有工作 | 记录 defer、关闭当前待办并暂停本任务自动推进；显示“尚未提交训练。方案、代码和处理记录已保留”及“重新查看方案” |

“重新查看方案”为只读，不恢复执行或默认批准。再次提交前检查待办和方案仍有效，
旧待办已关闭/过期时须新建请求身份后才能确认。重复确认使用同一 command_id，
响应丢失先查收据，不重新提交训练。

**首版治理限制不改变卡片结构。** 已有有效预授权且范围匹配时，按钮可标为
“确认本次执行并训练”，说明正在使用已有授权；无授权时显示“等待训练授权”，
主按钮禁用并列出缺失条件与管理员处理入口。App 确认不能创建 Campaign 授权或增加预算。
在线授权按第 07 章独立建设，Host 通用工具确认不能替代治理授权。

### 7.3 完成、延后与停止

训练验收完成保留“数据、代码、Job、Run 和训练产物已关联”及“查看验收证据”。
点击选择训练/验收阶段并打开产物，不重新执行验收。
仅完成 smoke 时明确“训练链路 smoke 验收完成；完整训练效果尚未验收”，不能声称模型质量目标达成。

数据任务对应“数据、处理记录和交付产物已关联”，展示清洗结果与质量报告。
延后、停止、失败都保留已产生记录；恢复按钮根据真实状态与权限显示。

## 8. 右侧过程详情：三个标签均为首版范围

标题“过程详情”，标示选中阶段、Attempt（如有）与最后更新时间。
开关仅控制可见性；重开保留阶段、标签和文件选择，不影响执行。标签切换不改变阶段。
正式环境把原型“示例”标记换为真实来源或同步状态。

### 8.1 产物：数据处理

包括数据类型、类别/Schema、有效/异常数量、隔离方式、train/validation/test 切分，
清单、报告、完整性/隔离/确定性切分/digest 检查。
原型有效图像 24,997、异常 3，train/val/test 为 22,497/1,250/1,250，
仅为样例；实际值须来自报告，关联数据身份与观察时间。

保留 dataset-manifest.json、split-manifest.json、data-quality-report.json 列表及内容预览，
不能只列文件名。未生成时说明原因，不把缺失值当成零异常。
测试集仅展示允许披露的数量、封存与身份，不展示样本/标签或用于调参的测试指标。
非训练 CSV 任务改为字段、行数、缺失/重复、编码、规则、输出数据与质量报告，不强制训练切分。

### 8.2 产物：项目文件与差异

保留可点击文件列表、增删改标记、当前文件名和**面板内行级 diff**。
“前往 Host 查看”可作补充，不能替代原型内容。
原型列出数据加载模块、scripts/train.py、configs/smoke.yaml、tests/test_galatea_contract.py；
产品列表来自真实 file-change 事件与受限文件快照。

每项绑定 change_id、stage_id、attempt_id、相对路径、操作类型、base/current digest 与可用 revision。
新增显示新增行，修改基于真实基线，删除显示旧内容。同文件多次修改可选变更批次，
不能拿最新工作区内容冒充旧 Attempt 结果。超长 diff 分页/折叠，二进制或已清理内容说明原因。

下方保留“数据与切分绑定 / 固定 Ray 入口 / 无训练的配置检查”的 running/passed/failed 与错误。
“通过”必须来自检查结果，不能由文件写完推断。选文件、展开差异、复制路径均为只读。

### 8.3 产物：训练、指标与证据

提交前展示数据版本、冻结 split、不可变 Release、配置与授权范围，
Job/Run 标为尚未提交，不生成假 ID。提交后按事实展示 operation、Ray Job、MLflow Run、
运行配置、各系统状态与观察时间。

指标包含名称、数据划分、值、步数与时间。train_loss、val_accuracy 只是原型样例；
缺失时显示“等待首个指标”，其他模型使用实际指标，不固定为 Cat/Dog 或 accuracy。
系统状态不一致时分别展示并标为对账中，不合并成成功。

验收清单包含 Checkpoint 上传与回读、报告、Ray 时间线（能力可用时）、Job/Run 终态一致性。
每项可看 artifact/evidence、结论与失败原因；只有验证过才显示通过。
保留 smoke 范围提示，完整效果与最终测试验收独立呈现。

### 8.4 日志

按阶段与 Attempt 展示时间、来源、操作、摘要、状态：

- 数据：skill、read、check、write、freeze。
- 代码：Skill 加载、逐文件变更、入口/配置检查。
- 训练：plan、authorization、release、submit、tracking、train、artifact、verify。
- 控制：等待确认、暂不训练、停止请求、真实停止结果、恢复。

支持展开允许披露的调用参数、输出与错误，并定位所属原生会话/消息。
无法关联阶段的源事件放入“会话记录 / 未归属”，不猜为当前阶段。
分页与增量游标读取，可筛选错误、来源、Attempt，跟随尾部可关闭，复制内容脱敏并标明截断。

原生操作、治理摘要与 Ray stdout 是不同来源。现有治理未提供 raw logs 时，
**仍保留日志标签和真实可用记录**，对应区域提示“当前接口未提供原始训练日志”。
不得删除整个标签或用静态示例填补。后续日志适配器需权限、限量与保留策略。

### 8.5 项目绑定

| 主展示字段 | 内容 |
| --- | --- |
| 项目 | 名称、project_id，与侧栏一致 |
| 工作目录 | 受限分配的目录，可复制，不含凭证 |
| 数据来源 | 原始引用、不可变版本与清单身份 |
| 参考项目 | 用户指定或 Agent 确认使用的参考；没有则显示未指定 |
| Agent 会话 | 自动关联的会话名称、绑定状态、查看入口 |
| 训练授权 | 有效范围、过期/缺失原因；数据任务显示不涉及训练 |

高级折叠区展示 task_id、Host/session/thread、plan_revision、operation/job/run 等追踪标识；
主界面优先人可读名称。绑定为可信服务只读投影，不能任由模型或前端编辑。
切换阶段不会改变项目/会话；执行绑定随选中 Attempt 更新。

### 9.2 初始化与恢复

1. new App(...) 后注册 SDK 回调，再 App.connect()；入口 task_id 只是选择意图。
2. get_workbench 返回经鉴权绑定、Task 快照、首屏时间线、各源游标。
3. get_workbench_events 更新公开消息/过程投影，get_task_events 更新业务事实；
   两种游标独立，不拿日志时间戳当全局事务顺序。消息内容修订使用独立更新游标，不能只拉新时间线项。
4. 阶段详情、文件、报告按需读取；其他任务或旧加载 generation 的响应丢弃。
5. 根据 allowed_actions 与能力声明显示操作；服务仍须再次校验。

按各源游标顺序处理并去重，缺口补拉，分页耗尽再推进完整游标。
CURSOR_EXPIRED 时重读快照，保留有效选择和未提交草稿。
聚合不承诺跨 Host/治理强一致；各投影有时间与游标，落后时显示同步中。

首版不用未支持的资源订阅。活动页每 2 秒增量轮询加抖动，无变化退避到 5 秒；
等待外部时 5–10 秒，后台页 30 秒，恢复可见立即更新。每数据流最多一个读取在途，
卸载取消读请求与计时器，终态停止高频查询。查询不能触发执行或外部恢复。

选中项、开关、滚动位置保存在 iframe 内存；跨挂载偏好使用受控服务，
不依赖 opaque-origin iframe 的 localStorage/Cookie。任务和已受理输入始终服务端持久化。
ui/update-model-context 只传任务、选中阶段/文件、版本与短摘要，Agent 使用前重读事实。
当前 Host 每聊天最多 32 个实例，上下文合计 256 KiB；建议单实例不超过 16 KiB。

## 10. 操作边界与异常状态

| 操作 / 情况 | 行为与反馈 |
| --- | --- |
| 查看阶段、卡片、标签、文件、证据 | 只读，不执行、不批准、不恢复 |
| 停止 Agent | request_control(interrupt_agent) 递增控制 epoch、撤销接续并中断当前 turn；确认前显示请求中 |
| Agent 已停但远程 Job 仍运行 | 继续观察，明确“Agent 已停止，训练作业仍在运行”；提供单独“取消任务并请求停止作业” |
| 停止本次训练 | 保留原型训练中按钮；request_control(cancel) 取消当前任务并请求停止关联作业，解释清楚范围；真实停止前保持 cancelling |
| 暂不训练 | 处理当前方案待办并暂停自动推进；不删除记录，不取消整个 Campaign |
| 恢复 | 重检输入、授权、计划后排队，不根据页面场景推断重跑步骤 |
| 未授权 / Release 未就绪 | 保留预算卡、缺失条件和入口，不显示成数据错误 |
| 失联 / 状态未知 | 最后确认事实、时间、对账进度；禁止直接重跑 |
| 版本冲突 | 保留文本并刷新；精确方案改变后重新确认 |
| 服务不可达 | 保留只读快照、标记过期，允许重连，不模拟成功 |
| 未知组件 | 通用卡显示有效字段，不阻塞其他区域 |

interrupt_agent 的暂停与外部排空见第 05 章，暂停不承诺冻结 Ray。
写操作由 Host 提供可信确认，App 不叠加相同确认框。
成功回执、业务已受理、实际执行成功分开呈现，未知结果先查原收据。

## 11. 响应式、可访问性与内容安全

沿用原型浅色中性工作区、紧凑卡片和路径等宽文本，状态同时使用文字与图标；
适配 Host 主题及暗色。不能改成大号统计看板并删减过程信息。

| 可用宽度 | 布局 |
| --- | --- |
| 大于约 900 px | 三栏，左约 180 px，右约 245–320 px，中间弹性伸展 |
| 约 600–900 px | 左约 165 px，详情移到中心下方，保留全部标签与内容 |
| 小于约 600 px / 窄内联 | 单列，品牌/发起/项目抽屉在顶栏；阶段横向滚动，详情在下方，预算纵向排列 |

断点按 iframe 实际可用宽度调整。窄屏折叠项目仍保留抽屉入口，不能永久隐藏会话。
输入框不遮挡最后消息；差异、错误、预算按钮均可键盘访问，详情开关焦点可预测；
标签遵循 tablist 语义，状态使用克制的 aria-live，轮询无变化不重复播报。

Markdown 禁用原始 HTML、脚本、危险 URL 与任意 iframe，产物按受控类型预览。
文件以 opaque ID 解析，服务校验归属、真实路径、符号链接边界、大小、媒体类型。
日志和样例脱敏，不把长日志、秘密或最终测试样本放入模型上下文。
下载遵守当前 Host 上限：8 个文件、单文件 8 MiB、合计 16 MiB；超限使用需另行实现的
受控制品服务入口，未配置时标为不可下载，不能把大型文件塞入工具结果。

## 12. 本章交付判定

以 P01–P15 的完整信息与操作为基线：六个原型场景均能用模拟数据独立查看，
并以真实两阶段任务验证动态连接。三个标签、真实文件 diff、方案调整/延后/再查看、
停止 Agent 与外部仍运行的区分，必须分别验证。

静态计时器演示、固定“Skill 已加载”、单独阶段列表、只有文件名没有内容、
只有授权状态没有预算卡，均不满足交付。完整矩阵见 [第 09 章](09-delivery-and-acceptance.md)。
